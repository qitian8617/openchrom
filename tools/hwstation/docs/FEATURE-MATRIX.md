# 功能迁移矩阵

对照本机快照里的温控插件（`PanelView` 与 GCWS 命令）和所附 HW SDK。原 OpenChrom 工程没有被修改，这些功能仍留在原程序里。

状态只有三种：本程序已做、只做了核心没做窗口、明确未做。

| 原功能 | 本程序 | 说明 |
|---|---|---|
| 手工填写地址后连接，`HELLO PC` | 已做 | 空主机、端口 0、主机名都拒绝。不扫描网段，不预填 8234 |
| 断开 | 已做 | 若当时在加热，记为停止未确认 |
| 仿真 / 离线 | 已做 | 启动默认仿真。离线停止不发网络 |
| 进样口 / 检测器 / 柱箱目标与当前 | 已做 | 未知或过期显示“未知/过期”，不用 0 代替 |
| 氢气、空气压力 | 已做 | 有 `h2`/`air` 时按 MPa 参与 0.1 门槛。只有 `adc1`/`adc2` 时仍解析并显示，但标明单位未确认，不能开门控 |
| 温控启动气压门槛 | 已做 | 两路新鲜且都 ≥ 0.1 MPa。快照 UI 源码里没有这道客户端门槛，按任务里的既有设备规则在发送前拦住。固件是否同样拒绝，快照无固件源，未验证 |
| 只开柱箱时立即 `START_OVEN_CONTROL` | 已做 | 与现有 MainView 一致 |
| 辅助区未稳时柱箱等待 | 已做 | 在线和仿真都要连续 10 次新鲜、偏差 ≤3 °C 的回报才发 `START_OVEN_CONTROL`。停止或故障会取消等待，不再补发 |
| 停止加热、急停 | 已做 | 四路都要 `WRITE_OK`，然后再读 `heat`。超时、缺状态或仍在加热都显示未确认 |
| 急停四条 STOP | 已做 | 不发送工作站 `data3=2` |
| 点火、空气阀开/关 | 已做 | 应答成功也不把火焰改成已着火 |
| 火焰未知 / 过期 | 已做 | 不编造成功 |
| 设备 `START_ACQ` / `STOP_ACQ` | 已做 | 不因火焰拦截。请求间隔沿用现有工作站的 100 ms，不把它当成已核实采样率 |
| 控制权 `DENIED` | 核心已做 | 收到 `DENIED` 就停止这条写入，不发第二次 HELLO 抢权。窗口没有单独的所有者轮询页 |
| 维护口令 | 已做 | 维护页可设置、验证、锁定。PBKDF2，无默认口令。未配置时不能写 PID 或本机备注。口令文件在本程序目录，不碰 `~/.openchrom` |
| PID 读取和写入 | 已做 | 三路可编辑。空值不能写。每次写入要维护解锁，并确认窗口里的柱箱/进样口/检测器数值。没有 1,0,0 占位发送 |
| 柱箱温程 | 已做 | 窗口有最高温度、平衡、稳定、循环和 8 阶（速率、温度、保持）。下载前检查 0–450、速率为 0 不得变温，并显示预计时长。读取失败不补 0 |
| 事件、秒表 | 已做简化 | 事件记录故障、停止确认和探测。秒表只显示本次设备采集时间，归零不发命令 |
| 手动探测地址、读取状态 | 已做 | 只探测操作者填入的那一个地址，发 `HELLO PROBE` 后关闭，不占控制权。没有全网扫描 |
| 温度校准设定 | 部分 | 可下载进样口和检测器设定。原表里的第二路真实温度列没有对应写命令，未另造 |
| 工程曲线、设备配置 | 部分 | 三路温度折线会随刷新绘制。设备配置可存本机备注；“下发设备配置”会说明协议不允许下发，并不发送 |
| 气路示意图 | 未做 | 原画布仍在 OpenChrom。这里用压力、火焰和阀按钮代替 |
| 进样序列、积分、校正、报告、白酒工作台 | 未做 | 留给 HW / 原工作站，本轮不重写 |
| 把采样送到 HW | 可测，未联调 | 必须由操作者填写并勾选已核实的间隔，才允许按该间隔投递。10 Hz 对 50 ms 会拒绝。不写 `HWFrequence.txt`，不补点。重写桥是可选试验，不是官方 DLL |
| 加载厂商 DLL | 已做加载器 | 路径自填。包内没有厂商 DLL。`hwbridge.exe` 是 32 位 |
| `HWFrequence.txt` | 明确不做 | 语法不在 cpp 里，禁止写 |
| 41–50 号窗口 | 明确不做 | cpp 有函数，`.def` 未导出 |
| Android、三块板、固件报文 | 未做 | 快照不含可改的固件；不新造报文 |

云端跑过的是 Linux 单元测试，以及交叉编译后的 PE 机器类型检查。没有启动 Windows 窗口，没有把命令送到真实仪器或真实 HW 窗口。

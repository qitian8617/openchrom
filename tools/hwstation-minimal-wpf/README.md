# 最小工作站接入（CtrlPanel）

只做一件事：连上当前色谱仪的 PC 采集口，把 `ACQ_DATA` 里的对数电压毫伏换算成 fA，在操作者明确放行后送给已安装的 HW 工作站。不改固件，不改 OpenChrom，不改 `tools/hwstation`，不改 `HWFrequence.txt`。

界面上始终有这句话：**无法验证设备样本新鲜度，仅接入验证，不用于正式定量**。设备在读失败时会重复上一个缓存值，帧里没有新样本序号。相同数值会照样送出，不能据此判断过期。日常用「开始分析 / 停止分析」。开始分析要等设备确认和一个真实点之后才通知 HW 取数。停止分析不是停热。

加热启动使用 2026-11-10 Android `GasSupply`：氢气和空气都要在 3 秒内、有限、且 ≥ 0.1 MPa。这不是新造门槛。缺一路、过期或读失败就不发送加热启动。停止加热始终可发。示意图还不是那一版 600×1024 画布，只接了同一条气压动画条件。这份 Android 包不声称与今天本机逐文件哈希一致。

## 数据

- 握手只发 `GCWS<TAB>HELLO<TAB>PC`。收到 `HELLO_OK` 才算拿到 PC 控制权。
- 开始和停止是二进制帧，不是文本 `GCWS START_ACQ`。文本那条是面板通知，不会启动 ADC。
- `START_ACQ` 载荷是小端 100 ms。`Y(mV) = vlog_uv / 1000`，可以为负，没有 +1.25 V 偏移。
- `V = Y / 1000`，`I(pA) = 100000 * 10^(V / 0.2)`，送给工作站的是 `round(I * 1000)` fA。
- 非有限值或超出 int32 就停止转发，不截断，也不改用板上的 pA 饱和值。
- 时间不是每 100 ms、帧序号或批序号断开，都判本次无效。不补点，不压缩，不为 20 Hz 复制样本。
- 每个真实样本先发 `(fA, 0, 3)`，下一条紧接 `(0, 0, 4)`。这是给空着的 B 通道补 0，不是第二路实测。开始 `(1,0,1)`、停止 `(1,0,2)` 和归零 `(1,0,5)` 不会插在这一对中间。A 失败就不发 B，B 失败就停止后续转发，不另造 A 点。
- DLL 返回 1 只表示找到 `HWClass` 并发出了消息，不是采集成功，也不是工作站已经在记录。返回 0 表示没找到窗口。

`examples/HWFrequence.proposed-10-10.txt` 只让本程序自己的门控认得 100 ms。它不会改安装目录里的 `HWFrequence.txt`，也不是让仍按 20,20（50 ms）运行的工作站改用 100 ms 的办法。选中安装文件 `20,20` 时转发保持关闭。

## 放到工作站旁之前

内容区使用白底、深色字，不跟随系统深色窗口。主机、端口、勾选句和状态应当能直接读到。这次没有在 Windows 上看过窗口；若这些字仍看不清，就不要连接，也不要点「允许转发」。

复制整个 `src\CtrlPanel\bin\Release\net8.0-windows\win-x86\`，不要拆开，也不要放进 `D:\HWGMP`。发布不是自包含的，机器上要已有能运行它的 x86 .NET 8 桌面运行时。包内没有厂商 DLL。只有在「厂商 DLL 完整路径」里填上你自己持有的 32 位 `HWSendData.dll` 并点「允许转发」之后才会加载；找不到就保持未就绪。程序不搜索、不复制该 DLL。

主机、端口启动为空，没有默认端口。先填这两项再点「连接」，状态出现 `HELLO_OK` 后才点「开始设备采集」。未转发时列表只显示。频率文件用「选择 HWFrequence.txt」只读打开；不要为了这次测试改安装文件。勾选句必须能读到全文：「我已知晓：曲线是对数电压毫伏换算的 fA，不能验证每个点是新转换，不能用于正式定量」。DLL 路径有效且频率文件通过之后，「允许转发」才会把随后的点成对送出。这不必等「工作站 A 开始」。「工作站 A 停止」只发 `(1,0,2)`，设备采集和转发都还在。停设备用「停止设备采集」，停转发用「停止转发」。断开和关窗口都不发停止采集，也不动加热或点火。

顶层窗口是手写的 `ControlPanelClass`，标题是“色谱反控（最小接入）”。WPF 只画在这个窗口里面，不会自动变成这个类名。互斥量是本程序自己的 `Local\HwstationMinimalWpf.ControlPanelClass.instance`，说明书里没有这个名字。若旧的反控程序也注册了 `ControlPanelClass`，第二次启动只激活带这个标题的窗口。

## 这一次 Windows 命令

在 `tools\hwstation-minimal-wpf` 下执行一次：

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\scripts\windows-one-pass.ps1
```

脚本先跑离线测试，再编译 x86 `CtrlPanel`。机器上若有 SDK 10.0.201，只在这个进程里钉住它，不改用户环境，也不调用 `install_windows.ps1`。成功后的程序在：

`src\CtrlPanel\bin\Release\net8.0-windows\win-x86\CtrlPanel.exe`

不要加参数去连仪器。离线测试不打开套接字，不加载厂商 DLL。

Linux 上只跑核心测试：

```sh
sh scripts/test-offline.sh
```

## 还要上电才能确认的事

源码里的新平均值大约 100 ms，不是已经在这块板上测到的 DRDY 间隔。工作站是否按 10 Hz 画图，取决于操作者以后有没有自己改频率文件。DLL 返回 1 之后，谱图有没有在记，也只能看着工作站窗口确认。
